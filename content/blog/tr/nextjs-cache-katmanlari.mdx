Next.js App Router'da "cache" tek bir şey değil, dört ayrı katman. Çoğu
"stale data" bug'ı, hangi katmanın devrede olduğunu bilmemekten çıkıyor.

## Katmanlar tek bakışta

1. **Request Memoization** — Aynı render ağacı içinde aynı `fetch` çağrısı
   bir kez çalışır. Ömrü tek istektir; invalidation gerektirmez.
2. **Data Cache** — `fetch` sonuçlarını istekler arası saklar. `revalidate`
   süresi veya `revalidateTag` ile tazelenir.
3. **Full Route Cache** — Statik render edilen sayfanın HTML/RSC çıktısı.
   Build'de oluşur, Data Cache invalidation'ı ile birlikte tazelenir.
4. **Router Cache** — Tarayıcıda, client-side gezinme için tutulan RSC
   payload'ı. Sunucudan invalidate edemezsin; `router.refresh()` gerekir.

## En sık yapılan hata

`revalidateTag` çağırıp sayfanın hâlâ eski veri göstermesi. Sebep genellikle
Router Cache: sunucu tarafı tazelendi ama tarayıcıdaki kopya duruyor.

```ts
// app/actions.ts
"use server";

import { revalidateTag } from "next/cache";

export async function updateProduct(id: string, data: ProductInput) {
  await db.product.update({ where: { id }, data });

  // Data Cache + Full Route Cache'i tazeler.
  // Server Action içinden çağrıldığı için Next.js
  // Router Cache'i de otomatik geçersiz kılar.
  revalidateTag("products");
}
```

<Callout>
  Kritik ayrıntı: revalidateTag'i bir Route Handler'dan çağırırsan Router
  Cache tazelenmez. Server Action'dan çağırırsan tazelenir. Mutasyonları
  Server Action'da tutmanın az bilinen ama önemli bir sebebi bu.
</Callout>

## Pratik kurallar

- Veri "kullanıcıya özel" ise cache'leme: `cache: "no-store"` veya dinamik
  render. Yanlışlıkla paylaşılan cache, performans sorunundan daha kötüdür.
- Veri "herkese aynı ama değişken" ise: `next: { tags: [...] }` + mutasyonda
  `revalidateTag`. Süre bazlı `revalidate` yerine olay bazlı invalidation.
- Debug ederken önce hangi katmanda takıldığını bul: sunucu logunda `fetch`
  çalışıyor mu (Data Cache), sayfa build'de mi render edilmiş (Route Cache),
  hard refresh sorunu çözüyor mu (Router Cache)?

Cache stratejisi bir kere doğru kurulunca, App Router'ın "varsayılan olarak
statik" yaklaşımı ciddi bir performans avantajına dönüşüyor.
